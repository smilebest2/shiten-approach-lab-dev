# 視点 / SHITEN — 接近の実験室

「観測者が変わると、大きさ・速度・距離の感じ方が変わる」を試す、完全クライアントサイドのWebプロトタイプ。

開発サイトの配信先: https://smilebest2.github.io/shiten-approach-lab-dev/

リポジトリ: https://github.com/smilebest2/shiten-approach-lab-dev / ブランチ: `dev`

## 大阪を走る / 実験02

[大阪の街を体験する](https://smilebest2.github.io/shiten-approach-lab-dev/osaka.html)。難波・道頓堀・心斎橋・本町・淀屋橋／中之島・梅田から出発地と目的地を選び、実在道路の複数候補を走る。難波〜梅田は約4.4〜5.3kmの曲がりのある候補を選択。高さ0.2 / 1 / 1.7 / 10 / 100m、速度5 / 30 / 100 / 300km/h。開始・停止・再開・方向変更に対応する。

左上のOSM実地図に現在位置・向き・ルート・目的地を同期表示。タップで全経路を拡大。「別のルートを選ぶ」で候補を変更、「出発地点へ」は同じ経路をリセットする。場所と道路名の案内表示も追加した。3Dとルートは静的配信、**ミニマップの地図画像のみOSMへ閲覧時アクセスする**。Leaflet 1.9.4を同梱。[v0.2の設計・通信条件・検証](OSAKA-ROUTES.md)、[測定結果](OSAKA-ROUTES-QA.json)。

データ・調査・検証・制約は [OSAKA.md](OSAKA.md)、測定記録は [OSAKA-QA.json](OSAKA-QA.json)。建物輪郭・道路は実在OSMデータ、高さ不明の建物や外壁は簡略化。道路の一方通行を含む交通規則・高低差は再現しない仮想走行。OSM由来データは[別ライセンス](osaka/LICENSE.md)（ODbL）で、ソーススナップショットと変換コードも公開する。

`osaka.html / osaka.css / osaka-app.js` は画面と描画、`osaka-engine.js` は実座標の走行、`osaka-stream.js` は保持・先読み・破棄、`osaka-worker.js / osaka-mesh.js` は別スレッドでの形状生成、`osaka/` は静的チャンク。既存の接近実験と同じThree.jsを使用する。

データ再生成は `osaka/source.json.gz` を展開して任意のJSONファイルに保存し、`node prepare-osaka.mjs <JSONのパス>` を実行する。クエリは `osaka/query.txt`。公開済みスナップショットの再利用でAPI再取得は不要。

球体の最小実験、犬の高さから人へ、虫の高さから葉へ、宇宙船から惑星へ、の4つの接近体験もある。これらは同じ接近エンジンを使う。Three.js 0.180.0をローカル同梱し、接近体験は実行時のCDN・サーバー処理・DB・外部APIを使わない。大阪のミニマップは上記の外部地図画像を使う。

## 起動

Node.js 20以降を使い、このファイルと同じ場所で:

```sh
npm start
```

表示された `http://127.0.0.1:4173/` を開く。ビルド・npm install不要。`index.html`のダブルクリックはES Modulesの制約で動かない場合があるため、HTTPで配信する。`server.mjs`は開発用で、公開サーバーには不要。

## 使い方

1. 視点を選び「スタート」。画面右上にも開始／一時停止がある。
2. 「一時停止」で即停止。「続きから」で再開。「最初から」で初期位置に戻る。
3. 全画面中も停止できる。Escapeで停止、Spaceで開始／停止（入力欄操作中を除く）。非表示タブにすると自動で一時停止する。
4. 「詳しく調整する」で速度、加速度、距離、対象サイズ、縦FOV、高さ、角度、余裕距離、4コースを選ぶ。移動に関わる設定を変更すると初期位置へ戻る。
5. 地面・周辺物体ON/OFFで、対象だけが迫る場合との違いを比較する。
6. 「同じ比率でスケールを比較」は対象を共通の球にし、同じカメラ軌道と描画を使って物理換算単位だけ変更する。
7. 「計測・比較の記録」でFPS・フレーム間隔・JSメモリ等を見て、接近評価とJSONを保存できる。回答の外部送信や自動保存はしない。

揺れは初期OFF。OSの「視差効果を減らす」等に対応する`prefers-reduced-motion`が有効なら揺れは無効。移動は必ずユーザー操作で始まる。不快ならすぐ停止する。動物の複眼・色覚の生物学的再現ではなく、位置とスケールの体験。

## パラメータと単位

内部座標は正規化単位。物理量は `内部値 × scale` で表示する。対象サイズはシナリオ形状全体の倍率で、カメラ高さとは独立。

|視点|1内部単位|初期高さ|初期の速度|初期距離（中心のZ距離）|
|---|---:|---:|---:|---:|
|球体|1 m|1 m|3 m/s|24 m|
|犬|0.5 m|40 cm|2.5 m/s|16 m|
|虫|25 mm|5 mm|62.5 mm/s|450 mm|
|宇宙船|3,390 km|基準軸から67.8 km|13,560 km/s|108,480 km|

宇宙は体験時間を短縮した架空の経路・速度。惑星の半径換算は火星程度だが、NASAの軌道・地形データではない。「高さ」は宇宙では地表高度ではなく中心軸からのYオフセット。距離メーターは衝突形状表面まで。

内部設定の例（ブラウザ開発者コンソール）:

```js
approachLab.select('lab');
approachLab.configure({speed: 3, acceleration: 0, distance: 24,
  size: 1, fov: 68, height: 1, angle: 0, gap: 0.08, mode: 'miss'});
approachLab.start();
console.log(approachLab.report);
```

`mode`: `hit` 直撃／`miss` 横へ滑らかに回避／`cross` 横切る／`stop` 手前で制動停止。停止・直撃コースでも高さが対象を越えると接触せず通過する。回避中はカメラの向きを固定し、横移動だけで進路を変える。`gap`は衝突判定形状に対する余裕。角度や形状により実際の最短距離は設定値より大きくなる。

## 検証

```sh
npm test
```

判定条件: 視角が単調増加、停止の余裕距離、20単位/秒＋加速時のすり抜け防止、回避・横切りの最短距離、30/60/120fps相当の刻みの整合、一時停止時の位置不変、0.025〜3,390,000倍の物理換算で同じ投影となること。

## 現時点の問題点

- **主観的な「うわ、ぶつかる」の最終合格は未判定。** 遠方・中盤・終端の画像、実際のカメラ軌道、角度曲線の技術確認はした。人間の評価を得るための記録UIを用意した。
- **iPhone / Android実機、Safari / Firefoxは未測定。** タッチ・縦長画面のエミュレーションと実機のGPU・熱・省電力は別。
- **犬と葉の衝突は保守的な箱近似。** 正確な葉の縁や足の曲面に沿った最短距離ではない。犬の見た目の足表面より手前で停止する。球体・惑星は球の解析判定。
- 角度・拡大率・tauは対象の球または外接球の値。犬・葉の実際の輪郭角度や画面被覆率とは一致しない。TTCは現在速度を保つ直線仮定で、加速・回避の予測値として使わない。
- 背景の木・石・草は視覚的手がかりで、個別の衝突判定は持たない。
- 惑星は自作の色模様。実在の地形・大気・軌道を再現していない。星も説明用背景。
- `performance.memory`はJSヒープの参考値で、GPU・ブラウザ全体のメモリではない。未対応環境では「null」。
- 高さを極端に上げた設定は対象を上から通過する。端末の実画面サイズ・視距離の較正はしていない。
- 直撃は接触点で静止する。破壊、音、点滅、カメラ回転は追加していない。
- 初回読み込みやFPSは端末と回線で変わる。ローカル配信の値を公開回線の値として扱わない。

次の優先順は、スマートフォン実機計測 → 同条件での人間の主観評価 → 衝突形状と表面詳細の改善。鳥・車・飛行機・葉から惑星への遷移はその後。[調査と拡張案](RESEARCH.md)。
